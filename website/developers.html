Run your first app locally

Requires Git, the .NET 10 SDK, and Docker. AuditDesk uses sample data. Browse its schema and configuration.

Install the CLI

The installer puts neoapps in ~/.local/bin. If needed, add it to your shell’s PATH as directed by the installer.

curl -fsSL https://raw.githubusercontent.com/Neopric-Inc/NeoApps.AI-CodeGenerator/main/install.sh | bash

Preview the app plan

Open the preview path printed by the CLI to review the schema, screens, roles, and workflow rules.

neoapps preview AuditDesk \
  --schema "$HOME/.neoapps/samples/auditdesk/auditdesk.sql" \
  --ui "$HOME/.neoapps/samples/auditdesk/auditdesk.ui.json"

Generate and run AuditDesk

Once you’ve reviewed the plan, run the app in Docker. The CLI prints the local app URL and sign-in details.

neoapps new AuditDesk \
  --schema "$HOME/.neoapps/samples/auditdesk/auditdesk.sql" \
  --ui "$HOME/.neoapps/samples/auditdesk/auditdesk.ui.json" --deploy
Architecture

How the compiler works

The assistant proposes a plan. The open-source compiler turns the approved schema and configuration into an application.

LLM / MCP clientClaude, Cursor, Codex
Declarative app planMySQL schema + JSON configuration
NeoApps compilerValidate, preview, generate
Generated app.NET 10 API · server RBAC · audit log · MySQL · React PWA

Plan-First Execution

The assistant drafts the schema and configuration. The preview checks the plan and shows the data model, role permissions, and allowed state transitions.

Zero-Trust API Layer

The generated API enforces role permissions, tenant and row scopes, and configured lifecycle rules on the server. The UI follows the same rules.

Append-Only Audit Trail

When auditing is configured, tracked changes record the actor, time, action, and changed fields. Password-verified sign-offs can record who signed, when, and the statement they signed.

Local agent integration

Connect a local MCP client.

Add the local NeoApps MCP server to a supported client, such as Claude Desktop or Cursor. Your coding agent can inspect schemas, preview permission rules, and plan updates to existing apps.

The installer registers NeoApps in Claude Desktop when it’s installed. Restart Claude Desktop after installation. For manual setup, merge the neoapps entry into mcpServers in claude_desktop_config.json. Use the absolute paths printed by the installer in place of the example paths.

{
  "mcpServers": {
    "neoapps": {
      "command": "/absolute/path/to/dotnet",
      "args": ["/Users/you/.neoapps/src/NeoApps.Mcp/bin/Release/net10.0/neoapps-mcp.dll"],
      "env": {
        "NEOAPPS_HOME": "/Users/you/.neoapps",
        "DOTNET_ROOT": "/absolute/path/to/dotnet-directory",
        "PATH": "/absolute/path/to/dotnet-directory:/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin"
      }
    }
  }
}

Developer FAQ

Building, updating, and versioning apps

How to work with a generated application over time.

What stack does NeoApps generate?

A .NET 10 Web API with role-based permissions and Swagger, a React 19 and Material UI frontend, and a MySQL database. The local Docker setup also provides Redis and RabbitMQ for background jobs.

How do schema migrations work when my AI updates an app?

Run neoapps evolve AuditDesk --plan to compare the proposed schema with the live database and inspect the generated FluentMigrator migration. NeoApps backs up the database before applying changes. Drops require explicit opt-in, and renames need a mapping. Read the migration guide.

Can I version-control my app plans in Git?

Yes. Commit the SQL schema, UI configuration, and any migrations or custom code to your own repository. Review changes in pull requests and run approved builds and migrations in your CI/CD pipeline. Store deployment credentials in the pipeline’s secret store.
